AI Guardrails

Binding rules for AI agents in this repository. Each card summarizes one always-on rule in .cursor/rules/.

Core Safety 000

Scope, confirmation, and risky operations.

  • Do not delete files without explicit user confirmation.
  • Do not implement features without a linked story or task; ask if none exists.
  • Keep changes small and scoped to the current request.
  • Ask before refactoring code outside the current scope.
  • Before risky operations (data loss, irreversible changes, production impact), explain what will happen and wait for confirmation.

Git Workflow 100

No destructive or force git operations.

  • Do not run destructive git commands (reset --hard, clean -fd, history-rewriting rebase, etc.) unless the user explicitly requests them.
  • Never force-push (push --force, push -f) to any branch.
  • Do not skip hooks (--no-verify) unless the user explicitly requests it.
  • Do not amend or rewrite commits already pushed without explicit user request.

Database Safety 200

Migrations only; no production SQL.

  • Never execute SQL directly against production databases (including one-off fixes via CLI or MCP).
  • Produce migration scripts only; the user reviews and applies them.
  • Use the project's migration mechanism (e.g. EF Core migrations) instead of ad-hoc DDL in app code or chat-run SQL.

Security 300

Secrets, CI/CD, and deployment.

  • Do not read, log, commit, or expose secrets (.env, keys, tokens, connection strings, credentials files).
  • Warn if the user asks to commit secret-bearing files.
  • Do not modify CI/CD configs (.github/workflows, pipelines, deploy scripts) without explicit user approval.
  • Do not deploy or trigger releases automatically; deployment requires explicit user instruction.
